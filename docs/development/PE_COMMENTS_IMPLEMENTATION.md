# Комментарии физкультуры: реализация и проверка

База: `claude/repository-review-cmv02q`, `db676c3318cf16d861b8a767f396b9060af16315`.
Отдельная ветка: `test/physical-education-comments`. Merge не выполняется.

## Реализованный путь

1. При экспорте текущего журнала, либо при штатном сборе журнала в batch,
   bridge отправляет отдельный ограниченный запрос MAIN-hook. Только точное
   название «Физическая культура» после нормализации регистра/пробелов.
2. Hook ищет `__reactFiber$…` у текущих `markCell-…`, проходит ограниченную
   цепочку `return` к `memoizedProps.value.store` и вызывает только `getState()`.
   Используется подтверждённый путь
   `JR_GradeJournal.journal.lessonComments.apiData`, не придуманный API.
3. Записи связываются по `student_id` + `schedule_lesson_id` с первыми двумя
   частями DOM-ключа. Третья часть — controlFormId, не subject_id.
   Несколько controlFormId для одной пары, несколько stores, ошибки/неизвестная
   структура, превышение лимитов означают «Данные недоступны».
4. Каждый найденный непустой record учитывается один раз в текущем снимке.
   Повторное считывание заменяет снимок, не накапливает его. Совпадающие id
   не используются для дедупликации: уникальность этого поля не доказана.
   Тексты группируются по точному совпадению, без объединения синонимов.
5. Отдельный versioned request/response канал проверяет окно, origin,
   requestId, форму/размер ответа и контекст DOM/URL. Таймаут — 1500 мс.
   MAIN остаётся недоверенной стороной: source-маркер не аутентифицирует страницу.
6. Новый столбец справа добавлен в CSV текущего журнала (все/проблемные), CSV
   «Мой класс», предметные листы и лист «Ученик» общей книги, XLSX в ZIP
   по ученикам, книгу всех классов, предметные листы административной полной
   выгрузки и проверки итогов. На смешанных листах другие предметы оставляют
   поле пустым. В новом Excel lookup для однофамильцев выводится
   «Неоднозначное имя», а не чужие комментарии. Старые формулы не изменены.
   Аналитические сводки по классам, ДЗ CSV и DOCX-памятки не менялись.

Пример: `5 комментариев по доступным данным (3 — Без спортивной формы; 2 — освобожден)`.
Слишком длинный текст ограничен для Excel и явно помечен «текст сокращён».

## Ограничения и приватность

- Это **частичный снимок уже загруженного Redux-кэша**, совпавший с текущими
  DOM-парами. Это не гарантированный полный период и не подтверждение свежести
  на сервере. Виртуализация таблицы может ограничить набор DOM-пар.
- 22 записи при 24 индикаторах не превращаются в 24 комментария. Отсутствующая
  запись обозначается «Не найдены в доступных данных», не нулём.
- Не угадываются apiStatus enum, метаданные журнала, API-параметры и механизм
  загрузки недостающих записей. Ненулевой apiError блокирует результат.
- При смене контекста старый pending-ответ отклоняется; повторно использованный
  массив того же store в новом контексте отклоняется до замены массива.
  Изменение кэша на месте/его серверную актуальность доказать невозможно.
- Нет дополнительных fetch/XHR, dispatch, subscribe, hover, кликов по ячейкам
  или переходов ради комментариев. Существующая навигация batch сохраняется.
- В MAIN агрегируются только нужные тексты/счётчики. Они не попадают в общий
  raw/debug API store, marks events, console, telemetry или storage.sync.
  Для работы batch между навигациями **агрегаты с текстом** сохраняются
  исключительно в существующих `chrome.storage.local` результатах соответствующего
  сбора и удаляются вместе с ними по существующим правилам очистки.
  Это не шифрование: локальные результаты и скачанные файлы содержат комментарии.
- Реальные аккаунты, данные учеников и ключи не использовались.

## Изменения и baseline

Изменены только пять runtime-модулей: `marks-api-hook.js`, `marks-api-bridge.js`,
`hybrid-counter.js`, `class-auto-loader.js`, `admin-collector.js`.
`manifest.json` и остальные 20 runtime-файлов сохранены побайтно.
Подсчёт оценок, посещаемости, критерии итогов и Free/PRO не менялись.
Baseline хешей обновлён явно только для этих пяти разрешённых модулей;
инвентарь 25 файлов и все assertions сохранены. Сообщение проверки уточнено:
совпадение с baseline не означает отсутствие изменений относительно базы.

Применены прочитанные локальные Skills `mesh-tdd-workflow` (RED/GREEN),
`mesh-mv3-development` (MAIN/isolated bridge без изменения manifest),
`mesh-security-review` (messages, локальное хранение, экспорт),
`mesh-e2e-testing` (настоящий MV3 и deny-by-default fixtures),
`mesh-verification-loop` (реальные файлы и честное разделение статусов).

## Исправление определения предмета — 18 ноября 2026

В присланной владельцем выгрузке отсутствует сам столбец «Комментарии»,
поле «Предмет» пустое. Подтверждён воспроизводимый дефект `journalMeta()`:
при отсутствии `h1`, заголовке вкладки «МЭШ» и пустом/постороннем первом
listbox имя предмета не определяется, даже если название журнала видно в body.
Скриншот не устанавливает точный HTML-тег реального заголовка; это не доказательство
состояния Redux на живой странице и не объяснение прежнего падения CI.

Добавлено ограниченное резервное распознавание единственного явного заголовка
`Журнал <предмет> <класс>` в уже читаемом фрагменте текста страницы. Прежний h1
сохраняет приоритет; неоднозначные названия не используются как резервный источник.
Простое упоминание физкультуры не включает новую колонку.

Четыре regression-теста, включая создание реального CSV текущего журнала:
до изменения два FAIL по отсутствующему/постороннему имени предмета,
после изменения четыре PASS. Полный набор: 39 PASS. Дополнен E2E-сценарий
`pe-heading` с видимым заголовком вне h1, вымышленным классом и Redux fixture;
всего 18 сценариев (15 активных, 3 прежних GAP). Локальный MV3 остаётся BLOCKED.
Из runtime в этом исправлении изменён только `hybrid-counter.js`; его baseline
хеш обновлён явно. Получение Redux и правила подсчёта не менялись.

## Диагностика «Данные недоступны» — 18 ноября 2026

После исправления заголовка владелец подтвердил появление предмета и новой
колонки, но все строки содержат «Данные недоступны». Этот результат не позволяет
различить отсутствие Redux, отказ проверки схемы и таймаут MAIN-hook.
Корневая причина на реальной странице пока не установлена, guards не ослаблены.

Теперь отказ содержит только статический код: `Данные недоступны [C03]`.
Код возвращается по тому же ограниченному каналу и сохраняется в обычном
результате экспорта; отдельного debug-store/логгирования/телеметрии нет.
Произвольные reason/error, имена, идентификаторы, URL, apiStatus и тексты
комментариев в диагностику не попадают. Неизвестный входной код заменяется C12.
Никаких новых запросов, разрешений, изменений manifest и правил подсчёта.

| Код | Место отказа |
|---|---|
| C01 | Нет пригодного набора текущих ячеек: пусто, превышен лимит либо неизвестный формат DOM-ключа |
| C02 | Для пары ученик/урок несколько controlFormId |
| C03 | У одной из ячеек отсутствует единственное ожидаемое React Fiber свойство |
| C04 | В ограниченной цепочке React-предков не найден провайдер store.getState |
| C05 | Найдено несколько разных store |
| C06 | Не найден ожидаемый Redux-массив lessonComments.apiData |
| C07 | Тот же Redux-массив повторно использован после смены контекста |
| C08 | Запись не соответствует подтверждённым типам student_id / schedule_lesson_id / comment |
| C09 | Превышен лимит записей или текста |
| C10 | Изменился контекст во время чтения или передачи |
| C11 | MAIN-hook не ответил за 1500 мс; конкретная причина не установлена |
| C12 | Ответ не прошёл проверку формы/размера/кода |
| C13 | Уже выполняются четыре запроса считывания |
| C14 | Во время чтения возникло исключение; его текст не извлекается |
| C15 | Redux apiError не пуст |
| C16 | apiStatus не строка, как в исходном исследовании |

Новые тесты проверяют конкретные коды отказа, таймаут, allowlist/отбрасывание
посторонних полей и создание реального CSV с кодом. Полный набор: 43 PASS.
E2E теперь дополнительно требует C03 в синтетическом сценарии без React.
Локальный настоящий MV3 остаётся BLOCKED политикой браузера.
Следующий необходимый факт: код из одной ячейки выгрузки владельца;
полный журнал, имена и комментарии для диагностики не нужны.
