# Проверка результата

Прочитай `AGENTS.md`. Выбирай проверки по фактическому diff и влиянию,
не добавляй инструменты и не расширяй изменение ради прохождения checklist.

1. Сверь `git status --short`, `git diff --check`, tracked diff и новые файлы.
   Учитывай, что обычный `git diff` не показывает содержимое untracked-файлов.
2. Для текущей задачи только инструкций: проверь frontmatter Skills,
   существование ссылок, отсутствие исполняемых hooks и неизменность
   `manifest.json`/`src/`. Не утверждай, что прошли функциональные тесты.
3. Для JS: `for f in src/*.js; do node --check "$f" || exit; done`.
   Проверь JSON manifest, пути background/content_scripts/WAR и memo HTML.
4. Запусти существующие целевые тесты по карте зависимостей. Пока runner
   не создан, помечай функциональные проверки NOT RUN. Не выдавай
   syntax check, 0 тестов или выключенный тест за рабочую регрессию.
5. Для экспорта проверь реальный CSV или ZIP/XML; для UI — E2E расширения
   на синтетическом журнале. Учти пороги в нескольких модулях и storage.
6. Проверь чувствительные границы по `mesh-security-review`, без вывода
   секретов. `rg`-совпадение — повод изучить код, не вердикт безопасности.

Сохраняй exit status команды; при pipeline используй `set -o pipefail`.
Не выполняй автоматически `npm audit fix`, formatter, install, commit/push.
Build/typecheck/lint/coverage, не настроенные в проекте, обозначь N/A или
NOT CONFIGURED, а не PASS. Для каждого выполненного тестового набора укажи
число тестов и результат; FAIL/BLOCKED/NOT RUN перечисляй отдельно.

Результат: что изменено, команды/доказательства, проверенные гарантии,
непроверенные сценарии, следующий шаг. Локальная проверка не доказывает
работоспособность с реальной МЭШ; реальные аккаунты в этой работе запрещены.
