# Проверка границ безопасности

Прочитай `AGENTS.md`. Проверяй только разрешённый scope и его зависимости.
Не исправляй находки и не запускай полный cloud scan автоматически.

1. Manifest: узкие host permissions и WAR, неизменная строгая CSP,
   отсутствие нового remote code/привилегий/загрузок сторонних скриптов.
2. Messaging: MAIN и page content недоверенны. Проследи source/origin,
   форму/type payload и влияние на store/DOM/worker. Маркер `source`
   и `event.source === window` не доказывают доверенность скрипта страницы.
3. Worker: сообщения → tab URL/storage key/queue; опиши границы доверия,
   ошибки и жизненный цикл, не добавляй permissions профилактически.
4. DOM и заметки: строка → textContent или корректное HTML-экранирование.
   Не предписывай React/DOMPurify, отсутствующие в проекте.
5. Экспорт: CSV formula injection для `= + - @ TAB CR`, кавычки/локаль;
   XML escaping и типизация строк/формул в XLSX/DOCX. Не исполняй формулы.
6. Данные: только настройки в sync, собранные данные локально; тестовые
   профили/медицина полностью вымышлены. Нет загрузки HAR, cookies,
   токенов, реальных журналов или артефактов с персональными данными.
7. Supply chain: прочитай Skills и ссылки до установки; нет hooks,
   скрытых installers, telemetry, credential dumps или автокоммитов.
   `.env` не делает клиентский секрет недоступным пользователю расширения.

Для каждой находки запиши файл/место, путь вход → обработка → эффект,
условия воспроизведения, доказательство и неопределённость. Не называй
grep-совпадение подтверждённой уязвимостью и не обещай отсутствие всех уязвимостей.
Полный аудит — отдельная задача с доступным Codex Security workflow;
наличие cloud SKILL.md не подтверждает наличие его runtime/tools.
