# Тесты перед изменением поведения

Прочитай `AGENTS.md`, проанализируй зависимости. Не начинай реализацию
функциональности, если задача разрешает только инфраструктуру/документацию.

1. Определи реальный runner. Пока package.json и тестового набора нет,
   отметь отсутствие runner; не вызывай отсутствующий ECC helper или npm script.
2. Для существующей логики сначала зафиксируй наблюдаемое поведение
   characterization-тестом на синтетических входах. Не объявляй его
   нормативным подтверждением неизвестного контракта API МЭШ.
3. Для разрешённого исправления запусти тест-воспроизводитель: RED должен
   возникнуть из-за целевой ошибки, а не отсутствия браузера/зависимости.
4. Измени только разрешённую логику; повтори тот же тест до GREEN,
   затем выполни зависимые регрессии. Не меняй ожидания, чтобы скрыть баг.
5. Рефакторинг — только если входит в задачу. Нет требования создавать
   checkpoint-коммиты, подключать ECC или достигать выдуманного процента coverage.

Для IIFE используй существующий публичный API. Если его нет, допустима
инструментация копии исходника в памяти Node `vm`, но не production-export
ради теста. Стабы `chrome`/DOM должны соответствовать реально используемым
callback/Promise API и `runtime.lastError`. Между realms используй
`ArrayBuffer.isView`, не `instanceof Uint8Array`.

Результат: сценарий, команда, подтверждённые RED/GREEN, регрессии и пробелы.
Документационные изменения проверяй структурно, не создавай искусственный RED.
